# Architecture & System Design

**Kizen** is designed as a hybrid modular application combining the ergonomics of a monolith with the strict boundaries of microservices. It is built to operate efficiently on a single host for solo-dev and small-team deployments while maintaining robust horizontal scalability paths.

## 1. System Topology

Traffic ingests through an edge proxy (Traefik/Nginx), splitting frontend and API concerns natively, with built-in telemetry channels designed for agent observability.

## 2. Core Constraints and Design Decisions

| Component | Stack Choice | Motivation |
| :--- | :--- | :--- |
| **Backend API** | Go (chi, pgx/v5) | Lightning-fast multicore processing and ultra-low memory footprint for single-host ALM. |
| **Data Layer** | PostgreSQL + SQLC | Single source of truth. Schema-driven Go type generation guarantees compile-time DB integrity (`sql/queries` to `internal/database`). |
| **Frontend** | React 19, Wouter, Vite | Serverless-ready components, seamless transition states with Framer Motion, and a highly responsive unified application shell inside `web/`. |
| **API Contract** | OpenAPI 3.1.0 | Absolute standard (`api/openapi.yaml`) mapping routes to Typescript clients and Agent integration functions. |
| **Serving** | Express + esbuild | Frontend bundling combined directly with a lightweight Node reverse-proxy (`web/server/index.ts`) for clean isolated environment delivery. |

## 3. Directory Layout (The "Modular Monolith" approach)

Kizen strictly bounds domain models. No service directly queries another service's tables.
- `services/ticket-service` - Ticket state transitions, backlog assignment, sprint calculations.
- `services/workspace-service` - Organization domains, isolated project tracking. 
- `internal/database` - Autogenerated strictly-typed PostgreSQL interfaces via sqlc (`sqlc.yaml`).
- `internal/postgres` - Connection pooling and retry backoffs.
- `web/` - Application presentation layer orchestrating unified marketing and tracking domains.

## 4. State Management (Target)

State transitions form the core of Kizen:
1. **Server-Owned Identifiers:** Issue IDs (`NW-143`) are atomically resolved within PostgreSQL sequences scoped per project to avoid concurrency collisions.
2. **Real-time Observability:** Designed to pipe diffs and mutations back immediately through standard streaming, powering human interfaces alongside real-time multi-agent ecosystems.
